Module socks5_handshake_flow 

Source
Expand description

SOCKS5 client handshake used for every upstream connection.

The proxy never accepts SOCKS5; it only speaks the client half of RFC 1928 to reach the upstream server, plus RFC 1929 username/password authentication when credentials are configured.

A session has three steps: greet with the supported authentication methods, authenticate if the server chose that method, then send a CONNECT for the destination and consume the bound-address reply. Host names are sent as-is so that the server resolves them remotely (the s in SOCKS5h).

connect_to_socks5_server performs the TCP connect and establish_socks5_connection drives the protocol exchange, both under SOCKS5_HANDSHAKE_TIMEOUT.
